# 内部源码模块与依赖

本文描述 `patrol_vehicle_chassis` 的内部实现和维护边界，不属于对外协议。

## 模块入口

产品代码按功能放在 `app/Core/User/` 的七个模块中。每个模块的 `src/` 只放 `.c`，`include/` 放公开 `.h`；只有需要内部接口的模块设 `private/`，用于存放私有 `.h`。

```text
app/Core/User/
├── system/       # RTOS 任务、产品配置、版本和故障注入入口
│   ├── include/
│   └── src/
├── motion/       # 底盘控制、标定、CANopen、转向和编码器反馈
│   ├── include/
│   ├── private/  # motion_internal.h
│   └── src/
├── cloud/        # 云端业务协议、命令、遥控会话、报文与发送调度
│   ├── include/
│   ├── private/  # cloud_internal.h
│   └── src/
├── mqtt/         # 公共 MQTT transport 的产品薄适配与 trial/runtime 接口
│   ├── include/
│   └── src/
├── ota/          # OTA 服务、镜像信息与配置持久化适配
│   ├── include/
│   └── src/
├── board/        # 产品平台接口与公共板载 I/O 电源业务适配
│   ├── include/
│   └── src/
├── common/       # 日志、时间基准和定点格式化
│   ├── include/
│   └── src/
└── modules.cmake # 产品源文件清单及模块头文件可见范围
```

`app/Core/Src`、`app/Core/Inc` 继续保存 CubeMX 生成的板级入口；HAL、FreeRTOS、`platform` 与 `shared` 的位置保持各自既有边界。

| 模块 | 职责 | 状态和依赖边界 |
| --- | --- | --- |
| `system/src/patrol_rtos.c` | 任务创建、优先级、健康位、看门狗、CAN/UART HAL 适配 | 不保存标定会话和运动执行器状态；实现 `PatrolRuntimePort_*`，在 10 ms 安全任务推进公共板载 I/O |
| `system/src/patrol_config.c` | Patrol 产品配置默认值、校验和运行时副本 | 使用 `PatrolRemoteConfigV5_t`；持久化通过中性的 `OTA_Info_*` 边界，Platform 不解释产品 Config 布局 |
| `motion/src/patrol_runtime.c` | 反馈组装、坐标纪元、运动门禁、CANopen 执行/诊断仲裁 | 通过可替换端口读取时间、进入临界区、检查 Bus-Off/OTA 和提交 CAN 帧 |
| `motion/src/center_calibration.c` | 首次建标会话、点动、稳定样本、编码器写入确认、失败证据 | 公共 `CenterCalibration_*` 接口不暴露 HAL/FreeRTOS 类型 |
| `motion/src/bench_steering.c`、`bench_drive.c` | 厂商转向和双驱动执行状态机 | 步骤使用具名枚举；原有诊断数值和步骤顺序保持不变 |
| `cloud/src/cloud_service.c` | EC800/UART 生命周期、Topic 身份、OTA 任务推进 | 唯一 DMA/AT 字节入口；连接和接收状态由公共 transport 持有 |
| `cloud/src/cloud_commands.c` | 公共控制和内部运维命令的分发 | 公共控制继续交给 `RemoteService`；内部配置、标定和 OTA 响应独立处理 |
| `cloud/src/cloud_messages.c` | JSON 编码、心跳、状态、诊断、日志分包和响应构造 | 保留字段、Topic、QoS、整数序列化和长度限制 |
| `cloud/src/cloud_tx.c` | 响应优先级、事件上报、空闲/活动周期、发布完成处理 | 保留 PUBACK 序号确认及重启响应完成顺序 |

## 能力分层

| 层次 | 当前能力 | 边界 |
| --- | --- | --- |
| ABox Platform | `ABoxEc800*`、`ABoxMqtt*`、`ABoxHttpsUfs_*`、`ABoxBootV2*` | 公共硬件、协议和状态机保持 ABox 命名；产品仓不建立第二套 Patrol MQTT runtime |
| 产品仓通用能力 | `OtaService_*`、`OTA_Info_*`、Cloud service、MQTT adapter | 使用中性能力名；`OTA_Info_*` 只负责 OTA/config Flash 持久化，不因此上收为 ABox 能力 |
| Patrol 产品能力 | `PatrolConfig_*`、`PatrolRemoteConfigV5_t`、`PatrolRuntime_*`、`PatrolRtos_*`、`PatrolDiagnostics_*`、底盘运动/转向/标定 | 承载车型配置和安全语义；Config V5 经 `PatrolMqttConfig_FromV5()` 转为 `ABoxMqttConfig` 后才进入 Platform |

当前正式产品配置格式仅为 Config V5。Config V3/V4 只属于开发历史，不进入正式运行路径；公共 MQTT V4 与 Config V4 是完全不同的版本概念。

`motion/private/motion_internal.h` 与 `cloud/private/cloud_internal.h` 仅供相应模块共享上下文。`modules.cmake` 按源文件设置私有搜索路径，不向其他模块添加这些路径。运动和云端各使用一个静态上下文，不分配新任务、动态对象或额外的 OTA 下载缓存。

`mqtt/src/mqtt_core_adapter.c` 保留原有业务调用接口，但实际连接、订阅、发布、重连、AT URC 和接收解析由 Platform `ABoxMqttEc800` 管理。产品只保存 Topic/ClientId、ICCID 查询和旧诊断枚举映射。OTA 在初始化时注册已有缓冲区地址；下载前经 `mqtt_stop` 等待关闭及排空，再通过 `workspace_borrow` 借出，完成或失败时归还后恢复接收解析。公共 runtime 通过 `mqtt_stop` 委托 transport 关闭连接，避免重复发送 QMTDISC/QMTCLOSE。

状态上报的 `transportDiagnostics` 用于定位 EC800 接收路径：`mqttRxLines`、`mqttRxDecoded`、`mqttRxDispatched` 是接收、解码和业务派发计数；`mqttRxRejected`、`mqttRxOverwrites`、`mqttRxTimeouts` 与 `ecDmaOverflows`、`ecDmaRestarts`、`ecDmaMaxBacklog`、`ecLineOverflows` 用于识别拒绝、覆盖、超时及 DMA/行缓冲积压。计数自本次设备启动累计，不证明某条控制命令已经执行。

## 修改规则

行走控制目标上限为 ±1000 rpm：`CHASSIS_MAX_RPM` 约束公共控制和本地 CAN2 入口，T12 将原始 ±450 映射到同一上限，`BENCH_DRIVE_MAX_RPM` 在执行器再次校验。T12 半量程对应 ±500 rpm，满量程对应 ±1000 rpm；转向速度分段为 300/180/90 rpm，角度分段阈值不变。当前控制层换向及行走执行器停车/换向超时为 6000 ms，其他门禁继续有效。

实体 T12 遥控器仅使用 CAN2 `0x10A.data[2]` 的 A 键状态控制使能，B 键 `data[3]` 保留但不执行控制动作。B 灯亮、灯灭及周期重发均不影响行走目标、转向、会话、使能或换向等待；A 关闭、摇杆回中、失联与安全故障仍通过现有停车链路处理。内部 `RemoteService_SetDriveBrake()` 行走禁用接口保留，未绑定任何实体按键。

运行层仅撤销行走执行器请求，完成两路零速、三组新鲜停车反馈、撤使能与状态确认，转向执行器及电源输出继续按原逻辑工作。发送前再次检查制动位，丢弃已经选取但尚未发送的行走命令。制动解除早于停车完成时，必须完成原停车序列后才能重新初始化行走。真实停车超时、反馈/驱动故障等仍服从公共故障处理，不保证故障时继续转向。Boot、Config V5、公共 MQTT V4 不变。

开关与摇杆帧均检查 100 ms 接收队列时效，旧时间戳开关帧不能覆盖新 B 状态。实体遥控还要求开关流在 300 ms 内持续更新；单独持续的摇杆帧不能掩盖 A/B 开关流丢失。故障复位不会解除 B 制动位；明确收到新鲜的 B 关闭状态才解除。该功能不改写驱动器快速停车或加减速参数，软件零速与撤使能证据不等于实测制动距离或机械抱闸验收。

- 任务周期、优先级、锁覆盖范围及发送前再次检查运动许可，均属于运行契约。移动代码时必须同时核对调用位置和时间戳来源。
- CANopen 只有一个未完成的 SDO 所有者。执行器响应可更新经校验的状态反馈，但不能完成诊断请求或推进诊断游标。
- 换向先发送左右零速，再等待三对新的低速反馈；超时、反馈过期和各故障门禁保持原有行为。
- 标定、普通运动坐标和有序停车的安全上下文不得互换；空闲标定允许瞬时陈旧反馈阻止点动，但不能掩盖终止故障。
- 编码器事务仍由 Encoder 任务执行。运行模块的编码器回调由调用方持有临界区；端口临界区允许嵌套。
- 新的静态缓冲区或函数调用层级必须核算 RAM 与任务栈。源文件行数和文件数量不作为优化目标。
- 新文件应先确定所属功能模块。源码加入 `modules.cmake` 的显式清单，公开接口放所属模块的 `include/`，内部声明放 `private/`；不得重新建立集中式 `Src/Inc` 或把头文件放进 `src/`。
- HAL、FreeRTOS、冻结的平台 Boot、Flash 分区及逐车配置不随产品目录整理而移动或重写。

## 验证方式

`tools/run_tests.ps1` 执行产品主机回归、独立 C 用例及平台 CTest。标定运行、停车仲裁、云端发送调度直接编译生产 `.c` 模块，通过硬件、时间、配置或报文构造桩测试，不再截取生产源码中的函数和代码块。

标定用例覆盖故障保留、坐标归属、±5° 点动范围以及 CAN 帧提交前许可被撤销；停车用例覆盖停机时诊断反馈新鲜度、卡住的停机超时和丢失节点回复；遥测用例覆盖空闲/活动切换、时钟回绕、事件优先级，以及响应在发布确认后才完成。

`tools/test_uart1_circular_dma.py` 检查 UART1 DMA 接收配置。`tools/build_bench_steering.ps1`（可加 `-Drive`）构建并通过 `tools/artifact_store.py` 发布对应候选。`tools/verify_bench_stack.py` 核对配置保存、标定提交和 CANopen 故障调用链的编译器栈报告，忽略源路径已不存在的旧报告，另外保留库函数、MQTT/HAL/中断的余量；这属于静态证据，不能替代设备上的栈高水位或现场验收。

正式发布遵守干净工作树、候选哈希一致性、冻结 Boot 和分区校验，最终以 `dist/release.manifest.json` 为准。结构整理和正式打包均不触发 OTA 或设备动作。

## 可信时间与有效期

common/time_base 复用公共 ABoxClock，common/time_sync 复用 ABoxTimeSync；公共 TIM2 2kHz原始计数扩展64位并输出毫秒，UIF由读取或ISR一致消费，必要边界为连续无消费少于32.768秒。HAL_GetTick返回该时基低32位，UTC由ClockSnapshot映射，不使用中断累计Tick推算UTC。未知CCLK时区模式拒绝bootstrap，但不阻止TLS平台授时。日志继续原RAM tick模型，跨校时映射记录使用BOOT+。

离散上电先验证请求原始有效期，查询已有结果，再使用一致snapshot判断信任及当前过期；请求timestamp不校验与当前UTC严格一致。四条RAM重放记录以UTC误差下界和monotonic双保护，容量未释放返回4003而非再次执行。该模型尚不提供重启持久账本。连续控制保留现有monotonic租约及运动安全仲裁，下电与stop仍先安全撤销目标。Topic缓冲区覆盖VID31字符，motion响应缓存320字节，固定故障邮箱及4KiB RAM保护区保持。
