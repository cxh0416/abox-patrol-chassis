# 配置 V5 与掉电恢复

## 固定布局

当前正式配置格式仅为 Config V5。`PatrolRemoteConfigV5_t` 固定为 400 字节：

| offset | size | field | default |
|---:|---:|---|---:|
| 396 | 1 | `mqtt_tls_enabled` | 0 |
| 397 | 1 | `mqtt_tls_profile_id` | 0 |
| 398 | 2 | `reserved2` | 0 |

SSL context ID 和 CA 正文不属于产品配置。工作包 6 只保存策略字段，MQTT runtime 仍使用
明文端口 19683，不链接 TLS candidate。

## 工作包 7 公共 Platform 接入约束

工作包 7 不再设计产品专用 TLS 开关。产品加载 V5 后必须把 `mqtt_host`、
`mqtt_port`、`mqtt_username`、`mqtt_password`、`mqtt_tls_enabled` 和
`mqtt_tls_profile_id` 映射为公共 `ABoxMqttConfig`；公共 Platform 不包含或解释
`PatrolRemoteConfigV5_t`。

`set_mqtt` 的 Broker、端口、凭据、`tlsEnabled` 和 `tlsProfileId` 必须作为同一个
candidate 进入公共 `abox_mqtt_trial`，依次通过 connect、subscribe、指定 proof、
持久化回读后才 commit。测试矩阵必须覆盖 plain→TLS、TLS→plain、TLS→TLS、
plain→plain 以及每阶段失败恢复。active 为 TLS 时，任何 TLS 失败都禁止隐式明文
降级；只有显式的明文 candidate trial 成功后才能改变持久化配置。

`get_info` 报告当前已提交 active 的 `mqttHost`、`mqttPort`、`mqttTls` 和
`mqttTlsProfileId`，不能报告尚未提交的 candidate。runtime 复用现有
`ABoxMqttTls_Start(..., enabled, ...)`，不得建立第二套 TLS 状态或编译宏开关。

加载只校验和接受 V5。V5 无效时进入既有 default/unconfigured 安全路径，保持
`remote_enabled=0`；不再解释或迁移 Config V3/V4。Config V3/V4 仅属于开发历史，不进入
正式运行路径。公共 MQTT V4 与 Config V4 是完全不同的版本概念，不得混淆。

## Flash 布局证据

| range | purpose |
|---|---|
| `0x08000000..0x08007FFF` | frozen Boot |
| `0x08008000..0x0803DFFF` | App, 216 KiB |
| `0x0803E000..0x0803E7FF` | config transaction recovery page |
| `0x0803E800..0x0803EFFF` | Boot State A |
| `0x0803F000..0x0803F7FF` | Boot State B |
| `0x0803F800..0x0803FFFF` | OTA_Info/config and motion fault journal |

恢复页来自原 App 上限的最后一个 2 KiB 页；链接脚本、产品 OTA size 校验、调试/候选/正式
打包校验均把 App 上限收紧到 `0x36000`。Boot 起点、App 起点、Boot State A/B 和配置页地址
不移动。冻结 Boot 仍能安装现有远小于 216 KiB 的镜像；工作包 6 App 不会链接到恢复页。

## 事务与恢复

配置页不能用同页双副本提供掉电保证，因为页擦除会同时删除两个副本。每次整页更新执行：

1. 若恢复页已有 CRC 和 commit 均有效的记录，先恢复旧主配置页。
2. 读取旧 `OTA_Info_t` 和最新一条有效 motion fault，擦除独立恢复页。
3. 写入恢复记录正文和 CRC，最后单独写 commit word；读回校验。
4. 擦除 `0x0803F800` 主配置页，写新 `OTA_Info_t`，再写回旧 fault，逐项读回校验。
5. 擦除恢复页后才报告保存成功。

任何时刻复位后，只要恢复记录的 header、长度、CRC、commit 全部有效，就幂等恢复旧主配置页，
完成验证后再擦除恢复页。若恢复记录尚未 commit，则主配置页尚未开始擦除，可忽略不完整备份。
因此保存的结果是旧值或新值，不会把同页双副本误称为掉电安全。motion fault 仍在原页尾部追加；
普通配置保存和掉电恢复都保留最新一条有效记录。

限制：这是内部 Flash 事务恢复，不依赖 EC800 UFS 可用性。正式发布或 OTA 镜像不得超过新的
216 KiB 产品上限。
