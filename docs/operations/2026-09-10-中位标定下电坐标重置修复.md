# 中位标定下电坐标重置修复

日期：2026-09-10

产品：`patrol_vehicle_chassis`

## 现场现象

0.2.20 在 `PATROL-CHASSIS-000` 上连续完成三次右转 1° 点动，每次均回到 READY，
两路相对角度一致、轮速为零且无执行故障。取消标定返回 `phase=0 / fault=0` 并下电后，
稍后的只读 `get_bench_steering` 却返回 `phase=4 / step=23 / fault=1`，冻结门禁
`0x0201`。设备重启后 `faultLatched=false`，说明这是 RAM 执行故障锁存，不是标定配置
写入或 Boot V2 回滚。

## 根因

取消标定会主动关闭车辆电源并撤销许可，CANopen 节点在掉电过程中可能留下 Boot-up
心跳。CAN RX 将该心跳记录为 `g_coordinate_reset_requested`。CANopen 任务已先因电源
关闭清除 `g_coordinate`，但旧逻辑随后仍无条件调用
`BenchSteering_Stop(..., cut_power=1)`，即使坐标已经无效、执行器已经空闲，也会制造
`BENCH_FAULT`。

## 0.2.21 候选修复与边界

- 下电分支先清除坐标；处理迟到的坐标重置请求时，仅当坐标仍然有效才锁存执行故障。
  因此正常取消/下电后的节点 Boot-up 心跳只会被消费，不会给空闲执行器追加假故障。
- 车辆仍带电且坐标有效时，节点 Boot-up 心跳继续触发断电和故障锁存；主动运动、停车
  序列或普通远控期间的真实节点重启安全语义不变。
- 下电后坐标仍为无效，下一次运动必须重新上电、取得新鲜转向/双驱/编码器反馈并重新
  建立坐标，不能沿用掉电前的运行坐标。

主机回归和 ARM 构建不能代替现场确认。OTA 后应重复一次“上电、开始标定、右转 1°、
回到 READY、取消并下电”的最小流程；等待节点离线后再读台架状态，必须保持
`phase=0 / fault=0`，同时 `coordinateValid=false`、无许可且电源关闭。
