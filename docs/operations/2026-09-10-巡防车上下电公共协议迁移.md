# 巡防车上下电公共协议迁移

日期：2026-09-10

## 范围

巡防车平台的 `power_on`、`power_off` 从内部 V2 `/internal/config` 迁移到公共 V3 `/ctrl`。设备信息、日志、诊断、配置和 OTA 继续使用相互隔离的内部 Topic。固件暂时保留内部上下电解析，仅用于已部署旧平台的迁移兼容；当前平台不再发送该格式。

## 当前实现

- 公共请求使用 `version=3.0`、`data.deviceType=vehicle_chassis`、`command=power_on|power_off` 和 `params=null`。
- 固件在既有公共控制 Topic 解析上下电，成功响应直接返回 `powerOutputOn`；下电先撤销远程许可和目标，再关闭车辆电源输出。
- 相同 `requestId`、相同报文重投只返回缓存响应；相同 `requestId` 对应不同报文时返回 `4001`，不执行第二个命令。
- 平台把普通公共控制响应作为设备操作响应处理；`cc:<session>:<seq>` 格式的底盘租约响应仍进入独立的实时控制链路。
- 主动状态中的 `powerOutputOn` 继续作为页面状态来源，不能由按钮点击或 MQTT 发布成功推测。

## 验证记录

- 固件 `tools/run_tests.ps1`：25 个 Python 测试、8 个平台 CTest 以及协议、底盘安全、台架配置和行走主机测试通过。
- 平台 `python -m pytest -q`：232 个测试及 8 个子测试通过；包含公共上下电发布 Topic、V3 Payload、QoS 1 和响应关联回归。
- ARM GNU 14.2.1 Release 交叉构建通过：App 起始地址 `0x08008000`，链接器区域使用 Flash 105720 / 223232 bytes（47.36%）、RAM 61192 / 65536 bytes（93.37%）。发布清单的 GNU size 口径为 Flash 105708 bytes、RAM 60120 bytes，不能替代链接器区域占用。
- 栈校验通过：已知标定调用帧 2512 bytes，加 1024 bytes 预留不超过 4096 bytes Remote 任务栈。
- Flash 布局校验通过：Boot `0x08000000`、App `0x08008000`、Boot State A `0x0803E800`、Boot State B `0x0803F000`、配置页 `0x0803F800` 保持不变。
- 正式 OTA App 为 `patrol-chassis-0.2.19`，长度 105720 bytes，CRC32 `C3DB29E6`，SHA256 `83D7F29C84779B1E5615DC30C36D5B567EA89FF5683625CCB739ADA1C21EB0B7`；`dist/` 已按清单整体替换。

## 证据边界与发布顺序

以上只证明源码、主机测试和交叉构建结果，未证明 Broker ACL、在车固件、继电器触点、负载电压或整车真实上下电。部署时应先升级并确认巡防车固件已支持公共上下电，再上线已切换公共命令的平台；不得先切平台导致旧固件无法响应上下电。
