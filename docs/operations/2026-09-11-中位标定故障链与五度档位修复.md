# 中位标定故障链与 5° 档位修复

## 历史证据边界

2026-09-10 17:45:27 建立的会话 `c-362607-2`，前五次左调 1° 的设备结果及后续读取返回可调整；两路原始值由 `-83815 / 87` 变化为 `-97160 / 3913`。这是传感器回报证据，不是轮胎实际转动验收。随后四次请求返回 `409 CENTER_CALIBRATION_NOT_READY`，拒绝门禁 `263153`，但标定仍为 READY、fault=0、failure.reason=none。

只读操作 `54614e2e-52db-4244-9346-1593525ab882` 取得执行器 FAULT、step=23、fault=1，冻结反馈门禁 `531 (0x0213)`。该值包含转向位置、轮速和行走状态字过期及坐标无效。源码中普通坐标看门狗与此路径吻合，但没有故障瞬间总线抓包，不能确认反馈过期的上游原因。首次“驱动器故障，未创建标定会话”也缺乏当时驱动状态快照，不能据此判定硬件故障。

本次审查修正此前结论的边界：统一断电分支会调用转向 `Stop(cut_power=1)`，旧实现覆盖首次执行器错误码，因此旧 fault=1 本身不能唯一定位首因。此前有关晚到 Boot-up 是断电唯一根因的判断未经现场瞬间证据证实。保留旧记录正文，本文件补充限定。

## 源码修复

- 标定起始清空普通运行坐标，整个活动标定会话不再从旧标定建立普通运行坐标；点动仍用原先捕获的双路相对起点，不进行实时重置或自动补偿。
- READY 短暂反馈过期阻止新点动；JOGGING／STOPPING 仍按既有新鲜度及 2° 偏差要求故障断电。节点重启终止标定并记录 `position_epoch_reset`。
- 底层断电前捕获失败，READY 也同步执行器故障、断电和故障锁存；转向执行器首次错误码不再被交叉停车改写。读取不清除拒绝证据。
- 整个标定会话保持关键诊断优先，位置／轮速／状态字先于低速诊断轮询；驱动故障寄存器继续读取。未放宽超时值或重试次数。
- 平台保留结构化 reason 机器码，兼容旧 raw_reason；故障／断电／过期反馈禁用点动和提交。上电后等待新的状态报告，不能把上电前缓存的健康或故障状态当作当前证据。
- 平台每次调整重新检查新鲜设备状态与最近设备标定结果，以设备接受的累计偏移计数，不累计被拒绝的点击。
- 保留左／右 0.2° 和 1°，新增左／右 5°；累计 ±60° 与当前驱动软限位不变。

## 验证与发布

源码目标版本为 `patrol-chassis-0.2.22`；源码版本不等于正式发布。最新正式版本仍以 `dist/release.manifest.json` 和哈希为准。

主机运行测试直接提取生产状态机函数及 CANopen 集成块，覆盖 READY 完成停止后的过期反馈、下次点动拒绝、活动点动故障、首次错误冻结、节点重启、普通坐标看门狗和 ±5°／±60° 边界。ARM 构建另行验证完整 RTOS 编译单元。平台测试经过实际 API 本地化链路，而非只测试未加工的模拟返回。

本次未授权自动点动，现场运动和 5° 实际轮胎角度仍待人工验收；OTA 成功也不代表运动或中位标定已验收。
