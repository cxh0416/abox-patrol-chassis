# 2026-09-14 0.2.24 停车反馈调度修复

修复同日左转 5° 后 STOPPING 阶段因行走状态字过期而失败的问题。现场首错见《左转5度后停车故障诊断》，本文件描述源码和主机验证，不替代现场复测。

## 修改

- 进入停车仍取消待处理诊断并优先发送撤使能；随后恢复执行器确认与诊断轮询交替，不再由停车状态永久独占发送机会。
- 停车诊断仅读取两节点状态字、转向位置和左右轮速，优先选取最久未更新且到期的安全样本；退出停车后恢复原诊断范围。
- 保持单一 SDO 事务归属、250 ms 反馈门槛、200 ms 停车时限和真实故障锁存；不重放撤使能写入，不自动恢复运动。
- MQTT 闲置降频和标定高频策略不变，平台接口无需改动。

## 主机与构建证据

专项测试提取生产 CAN 发送仲裁，连接真实 BenchSteering 和 PatrolDiagnostics 实现，模拟进入停车时 Node 2 状态字已 210 ms、撤使能确认延迟的场景。旧生产仲裁在回归中失败，新仲裁通过；另覆盖待应答时禁止第二事务、真实反馈丢失及撤使能超过 200 ms 仍故障。

完整回归通过：31 项 Python、平台 8 项 CTest 及产品 C 主机测试。ARM Release 行走候选构建通过，App 106256 字节，RAM 61192 字节，标定及 CANopen 故障栈检查通过。临时日志为 `out/logs/stop-fix-*.log`。

版本目标 `patrol-chassis-0.2.24`。正式产物仍按干净源码重建、与已验证候选比对后由 artifact_store 整体替换 dist；以正式清单为发布依据。后续设备刷写和运行证据另行记录。
