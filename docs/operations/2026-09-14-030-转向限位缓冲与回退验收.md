# 转向限位缓冲与回退验收

日期：2026-09-14。产品：`patrol_vehicle_chassis`；设备：`PATROL-CHASSIS-000`。

## 问题与实现

此前 0.2.29 在目标 -30° 时独立编码器约 -30.027°，触发范围故障；后续静止在 -30.045°，复位后仍无法建立运行坐标。原始证据见 `evidence/2026-09-14-030-limit-diagnosis/`，不能据此判定发生机械碰撞或驱动器内部过流保护。

0.2.30 指令上限保持 ±30°，反馈及驱动器 RAM 软限位采用 ±30.5°。轻微超调暂停行走，继续向外的请求转为该侧 29.5° 回退目标；向内和回中仍须通过所有其他门禁。两路反馈和操作输入均回到 ±29.5° 内才解除边界状态，持续满舵不会循环冲边。超过 ±30.5°、反馈过期、双转角偏差超 2° 或驱动故障等仍禁止运动。

台架补测发现原 `0x1F/0x0F` 位置触发会排队：边界退回目标在旧运动尚未结束时插入，后续反馈落后目标一档。按厂商原件《风得控新版-A同步伺服驱动器CANOPEN说明》物理第 82 页（印刷页 80）5.9.1，改用 `0x3F/0x2F`，保留绝对 Profile Position 模式，设置 bit 5 即时替换当前目标；应答超时仍不重放运动写入。未修改中位、位置比例、最高速度或永久驱动器参数。

平台 0.4.109 已部署至 server47：仅 `single_turn_4096_center0_limit30_margin05_v3` 允许从 30°～30.5° 缓冲区接管；接管初始目标仍钳制在 ±30°。页面显示边界回退提示，旧配置不会放宽。

## 构建与主机验证

最终候选 App：108832 bytes，SHA256 `3D6B3335458F30984F77EC4E8C141E426EC03D130953579ACE802768DEC5E908`。J-Link 读回与候选一致，Boot、逐车配置/故障记录页及另一 Boot State 页保持不变。正式包以 `dist/release.manifest.json` 为准，不能以早期同版本候选代替最终哈希。

32 项 Python、8 项公共 CTest 及产品 C 测试通过；覆盖双向轻微超调、硬越界、迟滞保持、向内恢复、反馈/驱动故障门禁和即时目标触发事务。平台 47 项测试通过，包含旧配置拒绝缓冲区、新配置接受 -30.045° 但拒绝 -30.501°。

## 现场记录与范围

原始日志和测试脚本保存在 [证据目录](evidence/2026-09-14-030-steering-margin/)，`index.json` 记录原路径、归档位置和 SHA256。

- 首轮候选从实际 -30.045° 接管，-30° 请求被限制到 -29.5°；随后逐步回中，双反馈 -0.007° / +0.054°，没有新范围故障。
- 首轮正向测试暴露旧位置队列问题，未作为最终验收通过。日志保留。
- 即时替换修订后，第一次直接从正边界回中仅等待 12 秒，断言时尚余约 3°；不是已到位。测试退出随后出现 REMOTE_DISABLED 首因记录，平台 power_off 应答超时；后续状态确认输出关闭，并通过正常 reset_motion_fault 复位。该历史记录保留，未清除故障证据。
- 最终验证使用 20 秒回中观察窗口，行走目标始终为 0。右侧 +30° 保持后目标 29.5°、反馈 29.499° / 29.701°；直接回中最终 0° / +0.018°，无锁存故障。

- 最终左侧 -30° 保持后目标 -29.5°、反馈 -29.499° / -29.647°；直接回中最终 0° / -0.036°，无锁存故障。CAN 抓包确认使用 0x3F/0x2F；两轮回中均仅发送单个零角度目标，控制续租保持有效。
- 结束时控制会话停止、许可撤销，power_off 返回输出关闭；get_bench_steering 显示 phase=0、fault=0、driveFault=0，编码器原始值 4094，两路行走反馈为 0。历史 lastFault 序号 3 保留。

本轮验证针对转向边界、回退和回中，不代表机械最大角度、负载行走、道路能力或此前后轮偶发现象已验收。PA0 状态不是接触器物理反馈。
