# 停车收尾超时修复（源码待现场验证）

现场证据见 `evidence/2026-09-14-center-alternating5/index.md`。0.2.25 左转 5° 后，停车写命令至 SDO 确认退使能为 180.511 ms；执行器已进入第 23 步，但收尾 NMT 尚未发出，总停车期限到期，锁存 fault=3。左右 1° 四次没有复现，不代表 5° 路径已通过。

当前修改保留 200 ms 退使能确认期限，过期响应不能转为成功。确认退使能后，重新计时，NMT 收尾单独限定 100 ms，并在没有未完成 SDO 事务时优先于新的诊断读取发送。等待退使能期间仍穿插关键诊断；反馈过期、驱动故障、发送失败仍触发原有保护。收尾不是实际静止反馈，不能据此放行普通运动或跳过反向零速确认。

主机验证：31 项 Python 测试、8 项平台 CTest 及产品 C 测试通过；新增真实生产调度回归通过。覆盖 181 ms 确认后跨过原总期限完成 NMT、200 ms 晚到确认拒绝、收尾 100 ms 超时和发送失败。未进行本次修改的 ARM 构建、正式打包或设备刷写，dist 仍保持原正式版本。

现场仍需用新固件完成左右 1°、左右 5° 测试，核对停车命令、状态字确认、NMT 收尾与平台阶段。此前第 22 步超时缺少 CAN 原始时序，本次修改不能作为它已解决的证据；若再现，需分别测量命令发送前等待和驱动器退使能耗时，不直接放宽 200 ms 期限。
