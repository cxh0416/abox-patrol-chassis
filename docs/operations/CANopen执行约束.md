# CANopen 执行约束

本文是内部产品实现约束，按当前源码维护，不属于对外交付协议。厂商原件见 [原始资料索引](../archive/2026-08-31-input/README.md)，正式包与候选状态见仓库 [README](../../README.md)。

## 总线和节点

| 总线 | 参数 | 用途 |
| --- | --- | --- |
| CAN1 | 500 kbps、11 位标准帧 | Node 1 转向、Node 2 双驱 |
| CAN2 | 500 kbps、11 位标准帧 | T12 实体遥控及本地 CAN2 控制服务，共用运动仲裁 |

Node 1 使用 SDO `0x601/0x581`、心跳 `0x701`；Node 2 使用 SDO `0x602/0x582`、心跳 `0x702`。只读模式仅允许 SDO 上传请求 `0x40`。台架转向许可仅授权 Node 1 的位置模式事务；Node 2 不得收到运行使能或非零速度命令。

## 双驱 Node 2

- DS402 速度模式：`6060=3`
- 使能序列：`6040=0x0006 -> 0x0007 -> 0x000F`
- 左右目标：`60FF`、`68FF`；左右反馈：`6069`、`6869`
- 默认使用 SDO。只有台架用 CAN 分析仪确认 RPDO2 映射确为 `0x302 = 60FF + 68FF` 后，才允许切换 PDO。
- 独立行走 RAM 许可允许 Node 2 在预运行状态通过 SDO 执行，当前源码目标限速 2000 rpm。按双驱原件状态字定义核对低位 Ready/Switched/Enabled，不能复制 Node 1 对 bit 5 的掩码。使能前写入两路零速；换向确认只计入双零速写入完成之后的左右新反馈。

## 转向 Node 1

- Profile Position：`6060=1`
- 当前位置：`6064`；目标位置：`607A`
- 新目标使用 `6040=0x003F` 触发，收到应答或完成下述只读核验后用 `0x002F` 清除 bit 4，保留 bit 5 即时替换语义。触发前先以新状态读取确认 bit12 为低，保留本周期确认基线。依据厂商原件物理第 82/83 页（页码 80/81）5.9.1/5.9.2；事务失应答仍不重放触发。
- 直行时读取 `6064` 保存为驱动器中心
- 机构轴理论换算为 `555.555556 count/机构轴°`；轮胎角度使用车型公共比例，不能把两者混用。
- 台架转向通过独立编译能力和 RAM 会话许可放行，仅 Node 1 可执行，Node 2 仍只读。
- 独立绝对编码器中心与驱动器中心必须分别保存

## 通信超时与只读核验

诊断上传请求每次等待 60 ms，最多重读一次。只有上层全部安全门禁通过、两节点可服务 SDO、驱动器无已知故障，且状态、转角、双轮及编码器采样年龄均不超过 170 ms 时才允许重读；250 ms 反馈有效期内预留 60 ms 事务及 20 ms 调度余量。每次等待超时累计 `sdoTimeouts` 并记录 `SDOREAD` 日志，重试本身不刷新任何采样时间、不直接永久锁存。余量不足或重试耗尽即释放事务，后续读取继续由现有调度和安全门禁处理；不能因此忽略真正的反馈过期。

活动期转向 `607A`、`6081`、`6040=0x3F/0x2F` 和行走 `60FF/68FF` 写入等待 ACK 达 40 ms 时，进入最长 80 ms 的只读核验，核验单次读取不超过 40 ms。原准备/限位/使能/正常停机事务保持各自失败处理；转向一般事务 200 ms、行走一般事务 100 ms 不被核验续期。核验期间两个轴都暂停新的运动写入，仅由原所有者发 SDO upload，保留原已发送值并记录 `ACKVERIFY`。

转向依次确认新状态为 Operation Enabled 且无 Fault、模式为 1、目标 `607A` 与原写入一致；轮廓速度另复读 `6081`，控制字另复读 `6040`。触发 `0x3F` 还要求触发前已确认 bit12 低、本次核验读到 bit12 高；清触发 `0x2F` 要求新状态 bit12 已低。目标寄存器相同、旧的高 bit12、写 ACK 或新遥控帧均不能单独充当本次触发已执行的证明。行走确认新状态、模式 3 以及完整双目标对：左目标未完成整个配对时，右目标应仍为上一对已确认值；右目标写入核验时两侧应均匹配本次给定。

核验成功后仍重新经过反馈时效、节点、双角度、标定、OTA、Bus-Off 等既有运动门禁。只保留最新遥控目标；未触发的旧转角及未发送的旧行走目标不会补发。已经发送的触发结果未知时，新目标不能取消其核验；确认后清触发再处理最新目标。换向零目标核验完成后，仍须三组新的低速反馈，不能用旧零速样本代替。

核验不匹配、Abort、无响应、任一门禁失效或期限耗尽，均转入下面的独立故障停机，发送行走零速、双节点撤使能并锁存。不存在“10 秒后仅凭遥控帧自动清锁或重使能”的路径。上述为源码和主机可验证行为，实际固件、候选与现场证据以 [CURRENT](../CURRENT.md) 为准。

## 运动门禁

当前源码的独立行走目标限制为 `±2000 rpm`，转向范围为 `±30°`，并受本次 RAM 许可幅度限制。独立编码器按单圈 4096 count、中位置零 解释；比例为 55.25 count/轮胎度。转向驱动器使用逐车保存中位及上电建立的 RAM 坐标，比例为 2710.8 count/轮胎度。RAM 软限位按 ±30.5° 设置并复读，不保存驱动器 EEP。

未标定、安全配置不匹配、单圈范围异常、反馈过期、两路角度偏差大于 `2°`、节点离线、CAN Bus-Off、驱动故障或 OTA 忙时禁止运动。方向反转必须先发送左右零速，双写入完成后连续三次左右实测绝对值不超过 `20 rpm` 才可反向；每次必须为新反馈。当前用户设置为 6 秒超时，未完成停车确认则撤销使能并锁存故障。

需要锁存时先进入禁止新运动的故障停机阶段，优先发送两节点 `6040=6`，再清行走双轮零速并读取 `6041`。两节点分别跟踪事务，转向漏应答不得阻塞行走撤使能；只接受对应状态读取确认，不能根据 shutdown ACK、旧状态或软件输出值认定完成。两节点确认后再正式锁存并关闭软件输出；600 ms 未确认或当前 Bus-Off 时先锁存/关闭输出，之后仍仅允许节流重试安全停机命令，未确认前不能清锁。正常定位触发和非零速度仍禁止重放，不改驱动器加减速、速度环、位置环或其他已调好的参数。

软件命令与真实停车仍需区分：撤使能可能存在驱动器内部延迟；通信断开时也可能根本无法送达。特别是驱动器手动接电、未经过 OUT1 接触器时，软件下电不能切断动力。现场验证须另行检查双轮停稳、转向停止及物理急停，不能仅依据构建、ACK 或回读宣称整车安全验收通过。

早期 ±300 rpm/±5° 阶段边界见 [历史首阶段需求与验收](history/首阶段需求与验收.md)。0.2.13 正式包行走限速为 50 rpm；不能用当前候选参数描述该历史正式包。
