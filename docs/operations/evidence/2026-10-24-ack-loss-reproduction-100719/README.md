# SDO 应答与运动故障锁存复现

监听条件：CANalyst-II 硬件只听，500 kbps；物理 CH1 接 CAN2（遥控接收器与 A-BOX 之间），物理 CH2 接 CAN1（A-BOX 与驱动器总线）。原始记录共 518.704 秒。

复现过程：

- CAN2 在约 164.188 秒后停止出现遥控帧，可能是操作者关闭接收器；故障发生前 CAN2 开关与摇杆帧均持续存在。
- CAN1 在约 120.56 秒后停止运动 SDO，只保留两节点心跳；App 和 4G 没有掉线。
- 板内首故障在停止开始前冻结：`reason=13`（执行故障）、`gates=0`，转向状态年龄 7 ms、行走状态年龄 90 ms、编码器错误 0。
- 转向执行器处于 `BENCH_FAULT`，`step=18`（定位触发），`fault=12`（写结果只读核验失败）。
- 行走执行器后来为 `fault=1`，属于故障联锁切电的次级结果。
- 故障前 CAN2 摇杆仍持续发送；故障时两轮反馈约为 `-1517/+1963 rpm`，转向状态字 `0x2237`、行走状态字 `0x0037`，两端均未报 CiA402 硬件故障。
- 板内累计 `sdo_timeout_count=7`；日志依次出现转向诊断对象 `entry=0`、`entry=1` 超时和重读。最终日志为 `FAULTSTOP disable mask=0/3 confirmed=0; latch`。

结论：

驱动器并没有在总线上完全静默。监听器能看到绝大多数 SDO 请求和应答，写 ACK 最大间距约 16 ms；但故障前一帧转向 `0x6041` 读请求在约 47 ms 后才看到下一应答，而活动写入的只读结果核验期限是 40 ms。固件因此进入 `steering fault=12`，再由两轴联锁进入执行故障锁存。该现象更像 MCU 在现有收发队列/任务调度下未在期限内消费应答，而不是驱动器持续漏发应答。

本记录证明故障锁存触发链，不证明电机已真实执行目标，也不替代现场机械验收。
