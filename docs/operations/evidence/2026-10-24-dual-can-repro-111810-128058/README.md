## 唯一一次漏 ACK

`256.266 s` 向 Node 1 写入：

`0x6040 = 0x003F`，请求帧 `2B 40 60 00 3F 00 00 00`

未捕获对应的直接写 ACK。`256.359 s` 的只读核验读取
`0x6040` 返回 `0x003F`，证明写操作已执行；随后继续写入
`0x002F` 并收到 ACK。该次事务没有导致后续通信停止，也没有
形成可见的故障锁存。

这说明新的 `60 ms ACK 等待 / 80 ms 单次读取 / 200 ms 总核验`
流程在本例中按预期把“未知写入结果”转成了可证明的只读核验。

## 唯一一次 Abort

`130.828 s` 对 Node 2 的 `0x2006:00` 只读查询返回
`0x06020000`（对象不存在或服务不支持）。该对象不是运动写入，
随后 Node 2 状态、轮速和故障对象读取均继续正常。

## 两次长时间静默

1. `101.922 s` 两个节点同时发送 EMCY `0x0010`/错误寄存器 `1`。
   此后 CAN1 TPDO 约 28.9 秒、节点心跳约 17.4 秒、CAN2 遥控输入
   约 28.6 秒不更新。节点随后重新 Boot-up 并恢复控制。该形态符合
   执行器/主控共同掉电或复位，不是单次 SDO 漏 ACK。
2. `783.719 s` 前先向 Node 1、Node 2 发送 NMT Pre-operational，
   `783.953 s` 后两路总线完全静默 337 秒；期间没有 EMCY。恢复时
   先发送 NMT Start/Pre-operational，再重新建立转向和行走会话。
   该段符合受控停机后长时间断电，不能归类为通信故障。

采集跨过上述两次断电/复位，因此不能把长时间总线静默当作正常
通信样本。除静默区间外，SDO 直接应答稳定，未再出现此前的频繁
漏应答和连续故障锁存。
