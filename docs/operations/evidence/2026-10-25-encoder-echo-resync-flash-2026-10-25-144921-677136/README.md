# 绝对编码器回显重同步修复

日期：2026-10-25  
候选版本：`patrol-chassis-0.2.89`

## 问题

现场 UART 抓包得到位置请求和编码器响应连续位于同一接收流：

```text
01 03 00 03 00 02 34 0B  01 03 04 0C 14 00 00 B9 67
|------ 请求 8 字节 -----| |------- 应答 9 字节 -------|
```

应答的地址、功能码、长度和 CRC 均正确，但原固件只准备 16 字节缓冲区，并
假设有效响应从第 0 字节开始。请求回显加位置响应共 17 字节，导致位置响应
持续被记录为格式错误，`encoder_count` 无法更新。

## 修复

- UART 接收缓冲区由 16 字节扩大到 32 字节。
- 新增接收流内有效帧搜索，允许有效响应前存在请求回显或无效字节。
- 仍严格校验从站地址、功能码、数据长度和 Modbus CRC。
- 零点写入同时兼容纯回显响应和“请求回显 + 设备响应”。
- 没有增加依赖车辆编号、线束或特定收发器的逻辑。

## 验证

- ARM Release 构建通过。
- `chassis_safety_test` 通过，包括纯响应、请求回显加响应、噪声前缀、
  损坏 CRC、位置响应、配置响应和零点写入响应。
- CAN2 协议主机回归通过。
- CAN2 栈检查通过。
- App、Full、State A/B 大小和哈希校验通过。
- State A 绑定本 App 大小、CRC 和版本，State B 为擦除态。

## 烧录

推荐完整安装：

1. `Patrol_Vehicle_Chassis_Full.bin` → `0x08000000`
2. `BootState_A.bin` → `0x0803E800`
3. `BootState_B.bin` → `0x0803F000`

已有匹配冻结 Boot 时，可改为：

`Patrol_Vehicle_Chassis_App.bin` → `0x08008000`

但仍必须同时写入本包 `BootState_A/B`。

禁止整片擦除，保留：

- `0x0803E000..0x0803E7FF` 配置恢复页
- `0x0803F800..0x0803FFFF` Config V5 与故障日志页
