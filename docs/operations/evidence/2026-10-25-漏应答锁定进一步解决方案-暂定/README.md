# 运动反馈优先级与受控停车修复

日期：2026-10-25  
候选版本：`patrol-chassis-0.2.91`

## 问题

现场双路监听显示，转向目标写入连续占用 CAN1 后，Node 2 行驶状态反馈从
最后一次正常 `0x6041=0x37` 到下一次响应约间隔 297 ms。Node 1 的一次
`0x6041` 响应迟至约 187 ms 才返回，超过诊断单次事务期限，导致行驶状态
超过 250 ms 安全时效。原逻辑随即把本次反馈延迟解释为执行故障并永久锁存。

该次记录中总线并没有超过 250 ms 的 SDO 未应答或 Abort；问题是串行事务
和运动写入的调度顺序，而不是驱动器已明确拒绝动作。

## 修改

- 关键反馈样本达到 150 ms 时提前进入紧急状态，预留一次 60 ms SDO 事务
  和响应处理时间。
- 紧急读取按真实样本年龄选择；新鲜 Node 1 位置 TPDO `0x281` 仍优先，
  不为已有实时位置额外发送 `0x6064`。
- 若低频诊断事务尚未超时，保留其唯一 SDO 所有权；事务超时释放后，下一条
  总线机会必须给紧急反馈，不能先发送排队的运动写入。
- 单次反馈过期时，先取消新目标并进入现有零速、三组低速确认、撤使能流程。
  会话在停车期间撤销后，受控停车状态仍持续到两个执行器完成停车。
- 250 ms 反馈安全时效没有放宽。节点离线、Bus-Off、OTA 忙、驱动器故障、
  停车超时或 CAN 发送失败仍进入原故障锁存和下电路径。

## 验证

- `test_stop_scheduler.py`：通过，包括紧急反馈抢占、低频事务超时释放、
  会话撤销后的多周期停车和反馈恢复后的正常收尾。
- `test_center_runtime.py`、`test_auto_center_runtime.py`：通过。
- `test_can2_center_calibration.py`：11/11 通过。
- `chassis_safety_test`、`bench_drive_test`：通过。
- ARM Release 构建、栈预算、CAN2 栈、冻结 Boot、版本标记、Full 拼接和
  Boot State A/B 绑定通过。

仍存在的完整套件失败：

- `test_identity_and_safe_defaults`：工作树既有热复位 SDO 写与静态断言冲突。
- `test_document_links_and_archived_evidence_references`：现有文档链接指向已
  不在当前工作区的旧证据目录。
- `bench_steering_test`：既有断言仍要求已淘汰的 `90 rpm` 轮廓速度，与当前
  `600/600/600 rpm` 配置不一致。

这些失败均未放宽断言，也不涉及本次反馈调度行为。

## 烧录

推荐完整安装：

1. `Patrol_Vehicle_Chassis_Full.bin` → `0x08000000`
2. `BootState_A.bin` → `0x0803E800`
3. `BootState_B.bin` → `0x0803F000`

已有匹配冻结 Boot 时，可改为：

`Patrol_Vehicle_Chassis_App.bin` → `0x08008000`

但仍必须同时写入本包 `BootState_A/B`。禁止整片擦除，保留：

- `0x0803E000..0x0803E7FF` 配置恢复页
- `0x0803F800..0x0803FFFF` Config V5 与故障日志页

## 验证边界

本包尚未烧录，不能替代实车验收。烧录全部配套文件后再复位，并在架空或具备
急停的条件下复测：

- 高频转向时 Node 2 状态、双轮速度和 Node 1 状态仍持续刷新。
- 接近 150 ms 的关键反馈读取优先于运动写入。
- 单次反馈过期时车辆先有序停车，不立即锁存。
- 若停车本身超时、发送失败或驱动器 Abort，系统仍锁存并撤电。
