# 0.2.28 中位置零修复与验收

日期：2026-09-14。产品：patrol_vehicle_chassis，车辆 PATROL-CHASSIS-000。

## 原因与修复

原固件把 2048（0800）写入编码器 0003 寄存器，现场编码器返回 01 86 01 83 A0（非法功能异常），没有改变当前位置计数。wyse 直接 RS485 实测与厂商资料一致：01 06 00 03 00 0F 39 CE 得到正常回显，并把当前位置设为 0。证据见 [直接串口测试](../evidence/2026-09-14-wyse-direct485/)。

固件 0.2.28 改为发送置零命令 000F；先取得静止反馈，清除旧标定，置零成功后连续三次新读数通过零点 ±2 count 校验，保存中位 0 并回读。失败仍禁止运动。绝对角度和上电运行坐标使用 4096 单圈最短差值，4095 位于零点负侧，不再被误判为大角度。±30°、双反馈偏差、离线及故障门禁保留。旧 2048 配置需要重新完成现场标定。

平台 0.4.107 已部署 server47；支持 single_turn_4096_center0_wrap_limit30_v2 配置，页面移除写入 2048 的错误提示，旧配置兼容显示。当前操作步骤见 [逐车标定](../巡防车底盘逐车标定与参数记录.md)。

## 验证范围

主机 31 项 Python 检查、8 项 CTest 及产品 C 测试通过，覆盖跨零角度、范围拒绝、三次验证和异常计数；ARM Release 构建通过。App 107176 字节，SHA256：1F1B6BEAC34D658D10E22B5990B94B39786D6B96E86436413755A10266151339。

J-Link 已刷入并读回一致，保留 Boot 和配置页，设备报告 0.2.28、CONFIRMED、OTA IDLE。用户确认的机械中位提交成功：phase=7，calibrated/profileReady/rangeValid=true，RS485 正常回显后读回 0。

右 1°、左 1°、左 1°、右 1°四次点动均正常结束，跨零到 4044 count 时解析约 −0.94°，无故障；返回原点附近后未再次覆盖已确认中位。控制器重启后配置有效，驱动上电恢复坐标且故障为 0，最后关闭电源输出。原始记录及哈希见 [提交与点动](../evidence/2026-09-14-028-center-zero/index.md)、[重启核验](../evidence/2026-09-14-028-center-zero/persistence-index.md)。
