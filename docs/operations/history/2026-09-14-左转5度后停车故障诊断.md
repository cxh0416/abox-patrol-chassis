## 已证实的触发与源码冲突

`center_gate_mask` 的 0x200 是 `CENTER_GATE_DRIVE_STATUS_STALE`，专指 Node 2 行走控制器 0x6041 状态字超过 250 ms 或没有有效样本。此次其它门禁位均未置位；不是双角度偏差或标定租约超时。快照 feedbackAge=228 ms 只统计转向位置、轮速及编码器的最旧样本，不包含状态字，不能用它否认状态字过期。

CANopen 任务进入 BENCH_STOPPING 时取消正在等待的诊断事务，并中止待发 CAN 邮箱；发送仲裁又通过 `g_bench.phase != BENCH_STOPPING` 完全禁止诊断读取。与此同时，标定 STOPPING 阶段仍要求全部关键反馈（包括 Node 2 状态字）新鲜，违反则锁存失败并下电。

停车 step=21 发送 Node 1 控制字 0x6040=6；step=22 循环读取 Node 1 0x6041，直到退出 Operation Enabled。此期间没有 Node 2 状态字刷新。停车等待上限为 200 ms，进入停车时样本已具有一定年龄，因而即使未到停车超时也可能先跨过 250 ms 新鲜度门槛。

源码中的诊断禁发与现场首次失败阶段、步骤、唯一失效门禁吻合，是本次最直接的固件原因解释。缺少故障瞬间逐帧 CAN 抓包及独立状态字时间戳，尚不能确认这一轮 Node 2 最后响应和停车每一步的准确时间，也不能排除额外调度延迟。不能把后续陈旧反馈或历史累计 SDO Abort 作为驱动器硬件故障证据。
