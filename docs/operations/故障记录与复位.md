# 故障记录与复位

适用于 patrol_vehicle_chassis 当前运动运行时。普通转向/行走执行故障和中位标定失败统一冻结首次原因；后续断电导致的离线不覆盖快照。指令参数拒绝不等于设备故障。HardFault/RTOS 崩溃仍走独立 Boot fault mailbox，不伪装成具有完整运动现场的记录。

先冻结 RAM，再立即执行原停机/下电保护。现有硬件缺少接触器反馈及可证明的安全供电保持条件，因此本版不启用带电等待故障补读，也不等待 MQTT ACK 才下电。记录标注样本年龄和未知值，不能承诺每次都得到厂商详细故障码；执行器读取到的故障状态字也进入冻结数据。来源/原因和执行器错误码不得混同厂商码。

动力关闭且 OTA 空闲后写入配置页尾部 0x0803FC00–0x0803FFFF，8 个 128 字节追加槽，CRC 最后提交。断写槽不会使旧完整记录失效；故障写入绝不擦除逐车配置。普通配置保存保留最近记录并压缩日志；槽满或写失败在状态明确标记 2，RAM 记录继续上报，不自动擦除配置。配置页总边界仍为 0x0803F800–0x0803FFFF，不占 Boot State。配置页本身的传统擦写断电风险不因此消失。

状态报告持续携带最近故障，网络恢复和控制器重启后仍可查看。页面显示“最近故障记录”，包括两路状态、码值和采样年龄；零码旧样本不能说明故障发生后无故障。故障记录不作为当前门禁。

页面“故障复位（保持下电）”先结束远控并关闭动力，再发 reset_motion_fault。复位不会自动运动，须重新接管并通过新反馈检查。驱动故障若仍存在，继续禁止运动；复位不能代替硬件维修。若响应不确定，查看最新状态，不能把按钮点击当作成功。

平台接管确认可复用该恢复流程：设备明确上报锁存故障时先下电复位，再上电等待新 MCU 就绪状态，之后建立新会话。它是操作员主动发起的恢复，不定时自动清除故障，也不恢复旧目标。复位失败或实际故障再次触发时，接管停止；物理故障和方向切换超时仍受原有锁存保护。

主机测试覆盖首次原因保留、缺失采样标识、下电/OTA 复位门禁、记录保留、Flash 断写/满槽及配置保存兼容；现场结果单独归档，不由构建通过推定。
