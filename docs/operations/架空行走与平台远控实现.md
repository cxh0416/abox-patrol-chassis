# 架空行走与平台远控实现

内部当前实现说明，适用 `patrol_vehicle_chassis`。最新正式产物以 `dist/release.manifest.json` 和哈希为准；当前台架候选行走目标上限为 ±500 rpm，现场验证范围以带日期的记录为准。

## 执行与保护

转向与行走执行器由 `PATROL_STEERING_EXECUTOR_ENABLED`、`PATROL_DRIVE_EXECUTOR_ENABLED`
独立编译；正式运动输出另由 `PATROL_CHASSIS_ACTUATION_ENABLED` 控制。正式编译选项以最新 dist 清单为准。
远控只建立公共 V4 控制会话；重启、MQTT 重连、停止、租约
失效或故障均撤销会话，不保存持久授权位。

Node 2 依厂商 SDO 示例进入预运行状态，经 `6060=3`、`6061` 确认、两路零速写入，
逐级执行 `6040=6/7/F` 并读取 `6041`。状态位按双驱原件第 24 页核对 Ready、Switched、
Enabled 和 Fault；不能照搬 Node 1 对 bit 5 的组合掩码。左右速度写 `60FF/68FF`，
0.2.14 的目标限制曾扩大到 ±200 rpm；当前台架候选上限为 ±500 rpm。实际转速存在控制偏差，不能把目标上限当成已测量的绝对速度上限。

换向先写左右零速，两个写入均应答后，连续三组左右新反馈均 ≤20 rpm 才发反向目标。
任何一侧旧样本不能重复计数，中间超标会清零计数。换向超时 2 秒锁存故障；停止先零速、
确认静止，再撤使能并读状态确认。SDO 应答超时 100 ms，不重放运动写入，失败关闭 PA0。
反馈、标定、双角度、节点、Bus-Off、驱动故障及 OTA 门禁持续有效。执行器读取到的
有效状态字也更新时间，但不完成诊断模块事务，不推进其轮询游标。

## 历史验证

0.2.10～0.2.13 的 10/30/50 rpm、三组换向反馈见 [行走证据](evidence/2026-09-08-bench-drive-0212.json)。不能将这些记录外推为当前 ±500 rpm 候选的实车验收。

## 平台

平台生成独占 `sessionId`；接管先发送上电命令，再建公共 V4 控制会话。MCU 独立判断
有效标定、运行坐标、双角度、反馈及执行器状态能否允许目标执行。平台不依据 profile
字符串、内部阶段、反馈年龄或门禁位放行运动。
0.2.14 / 平台 0.4.93 曾用于 20°/30°/40° 逐级机械范围测试。2026-09-09 的单圈编码器候选改造将正式页面档位收紧为 20°/30°，后端、许可和固件目标上限统一为 30°。
接管保持当前转角，行走初值为零；正常释放行走输入发零速并保持会话，正常释放转向输入发 0°
自动回中。立即停车、设备拒绝、浏览器失联和平台开关关闭均结束远控会话。设备无有效远控目标时，
本地回中可以独立执行；显式 `stop` / 下电及本地安全故障仍取消回中。
转向驱动器软限位在本供电周期按 RAM 中位设置并复读为 ±30.5°；不写入永久存储。
独立编码器须完成 0 中位置零标定并通过单圈范围门禁；这些源码限制尚不能表述为已通过机械范围或异常掉电恢复验收。
边界缓冲区的目标钳制和回退由 MCU 执行。状态 `steeringBoundary` 非零时平台提示松开或减小转向，详见 [车型参数](车型参数与台架转向实现.md)。平台停止响应仅表示请求已记录。
平台控制下发间隔 250 ms，浏览器超时仍为 750 ms，设备租约仍为 1000 ms。
临时会话采用 WAL NORMAL，减少每次续租刷盘；审计与配置连接保持原有持久化策略。
会话库独立于主库，控制调度独立于维护循环，避免日志写锁与维护耗时阻塞续租。

## 本地空闲回中

空闲或租约到期时撤销远控目标与行走授权；行走执行器先完成左右零速写入、连续三对新鲜实测
不超过 20 rpm、撤使能和状态确认。本地回中只使用转向执行器，不启动行走执行器，也不恢复会话。
停车完成前保持当时转向；边界缓冲区的保持目标限制在 ±30° 内。停车完成后在有效标定、运行坐标、反馈、节点、双角度、CAN、驱动器和
OTA 门禁全部满足时执行 0°。两路新鲜转角连续三组均在 ±1° 内才结束，重复旧样本不计数。
从发起到停车等待、准备和回中总计最多 30 秒；超时进入执行故障并撤销输出，不自动重试。
新的有效远控目标可接管；标定会话独占执行器；反馈失效、下电及故障立即取消本地回中。
显式 `stop`（含重复和其他会话的安全停止）保持停车，直到新控制目标被接受或显式上电才重新
允许空闲回中。MQTT 重连不恢复远控授权；若本地条件保持安全，回中由设备自行裁决。
回中期间保留 1 秒状态上报节奏，平台状态不能替代现场机械到位检查。


## 停控维护窗口与发布门槛

1. 部署仅支持新会话流程的平台时结束旧控制和标定会话，保留审计，并保持远控入口关闭。
2. 新运动候选须显式运行 `build_bench_steering.ps1 -Drive -EnableActuation`。`powerOutputOn` 只说明 MCU GPIO 命令状态，本车不存在独立触点反馈。在轮胎离地、硬件急停可用的台架上，以 CAN 状态、左右实测转速、转向状态/位置、独立编码器核对换向、停车、失联和故障路径。
3. 验证失败时停留在候选阶段。验证通过后，以已验收的同一 App 候选运行 `build_release.ps1 -BenchDrive -EnableActuation -VerifiedCandidate <候选 App 路径>`，经 `artifact_store.py` 整体替换 `dist/`；以 manifest 和哈希标识正式包。
4. 现场窗口内逐车 OTA，核对 Boot `CONFIRMED`、Config V5 标定回读、重新上线和状态报告。完成切换后再做现场运动验收。OTA/MQTT ACK 不能代替运动实测。历史 `0.2.45` OTA 确认不证明后续固件已安装；当前现场版本须按实时心跳核对。

候选位于 `out/candidates/bench-drive/`；发布与清理规则见仓库 [README](../../README.md)。
