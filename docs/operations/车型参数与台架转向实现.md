# 车型参数与台架转向实现

产品为 `patrol_vehicle_chassis`。本阶段只开展架空转向测试，行走输出禁用。

## 上电坐标同步（经现场问题修订）

0.2.8 上电后，ABox 和 wyse3040 均读取到驱动器 6064=-83815，而断电前为 -93256；独立编码器前后均为 2945。wyse 旁路抓到 2872 次 6064 应答均为 -83815。此前静止供电循环的结果不证明转向之后驱动器仍能保存当前位置。厂商对象字典将 6063/6064 定义为只读，项目实物资料说明该型号使用增量编码器。

用户据此确认：每车一次标定，之后每次上电静止建立运行坐标。0.2.9 使用独立编码器作为轮胎角度基准：反馈齐全、未使能、至少三组新反馈并静止 300 ms 后，将 `当前驱动器计数 - (当前绝对编码器计数 - 绝对编码器中位) × 公共驱动器比例 / 公共绝对编码器比例` 作为 RAM 中位。所有中间运算使用 64 位，溢出不得建立坐标。该过程不发送目标、不运动、不写 Flash；`coordinateValid/runtimeCenterCount` 可查询。

原标定驱动器中位继续保留在 V4 中，用于原已保存控制器软限位的坐标转换；新运行目标与驱动器角度反馈使用 RAM 中位。独立编码器中位始终是已保存的逐车标定值。上电首次使能前，读取 201A/2019，按 RAM 中位与标定中位的差平移限位，再收紧到轮胎 ±5°并写入复读；不保存控制器 EEP。同一供电周期再次使能只验证已应用的限位，不再次平移。限位更新中途停止或失败会断电，避免残留半组限位继续运行。

PA0 关闭后丢弃 RAM 坐标。已建立坐标后发生反馈失效、节点重新启动或标定变化时停机断电；禁止在运行中重新对齐两路反馈来消除偏差。下次供电重新建立坐标仍不自动开启测试许可。反馈门禁新增位 512 表示运行坐标未建立。

## 配置与兼容

车型公共参数集中在 `vehicle_steering_profile.h`：驱动器 2710.8 count/轮胎度、独立编码器 55.25 count/轮胎度、右转为正、双角度容差 2°。这些比例来源于本车人工左右约 ±10°采样，属于调试基线，未作为轮胎绝对角度精度验收。

每车只需维护两路中位和标定有效标志。V4 布局保持 396 字节，旧比例/方向字段作为配置兼容快照保留；不匹配公共参数的有效标定禁止运动，不自动重写。新车初始不标定，本车通过运维入口写入 -85123 / 3182，固件不按 VID 或默认值自动灌入中位。清除标定不会在下次启动自动恢复。

配置保存经 Flash 回读比较后才更新 RAM。常规 OTA 和重启不清除有效中位；更换传感器或调整机械安装后重新标定。

## 台架条件

现场确认采用现有 PA0 输出及 CAN/编码器反馈，不等待新增接触器反馈和本地按键。未配置的引脚始终不绑定；`contactorFeedbackAvailable=false`，台架就绪不能解释为真实触点闭合。

`PATROL_CHASSIS_BENCH_STEERING_ENABLED` 默认 OFF。`tools/build_bench_steering.ps1` 显式开启本能力并输出到 out，通用运动开关保持 OFF；编译能力存在也不自动使能。内部 arm 创建 RAM 许可和唯一 sessionId，15 秒内必须建立控制会话；控制租约最长 1000 ms。停止、过期、故障、重启均撤销，旧会话不得在重新 arm 后复用。执行故障保持锁存，需要排查后重启再开始；不得自动恢复运动。

台架入口拒绝非零行走目标、超出当前 1°/3°/5°幅度的目标；Node 2 仅发送 SDO 读取。使能前检查 Node 2 未 Operation Enabled、左右转速不超过 20 rpm。两节点、位置/速度/状态字、编码器配置和反馈、OTA、Bus-Off 及双角度门禁持续生效。

## 执行链

CANopen 任务统一调度诊断与执行事务，最多一个 SDO 等待应答；执行期间优先读取状态、位置、左右转速和驱动故障，暂停低优先级扩展对象。执行下载不重试，避免不确定的目标触发被重放。单次应答最长 100 ms，准备最长 5 秒，停止确认最长 200 ms。

Node 1 执行 NMT Start、读取 201A/2019 软限位、设置并确认位置模式、写入并复读 6080/6081=100 rpm、把 607A 预置为进入流程时的当前位置，再逐级执行 6040=6/7/15 并读取状态字确认。运行目标由中位及车型比例反算，必须同时满足软件幅度与驱动器软限位；607A 写入后使用 1F/0F 触发。

显式停止撤销使能并确认状态后进入 NMT 预操作，不发送回中目标。通信失败、反馈失效、状态异常等故障关闭 PA0，取消待发运动事务。停止撤使能未能在 200 ms 内确认也关闭 PA0；不能以 MCU 输出回读替代真实断电验收。

## 实测记录原则

先 ±1°，通过后再 ±3°/±5°，每个会话显式停止或验证租约到期；记录目标、6064、独立编码器、左右速度、状态字及停机结果。主机仿真覆盖反馈中断与错误报文，真实断链停车另需现场断链证据，不能用仿真或 MQTT ACK 代替。

2026-09-08 0.2.5 阶段 ABox CAN1 已恢复收帧，两节点反馈新鲜；保持轮胎不动的控制器供电循环中，两路计数均保持 -83815 / 3135。不再把不同次人工回正时的计数差视为已证实的上电漂移。

0.2.7 已完成最小中位保存及复读，OTA 状态 CONFIRMED；±1°、+3°收到跟随反馈。−3°已经到位，在保持约数秒后因反馈新鲜度门禁失效进入故障并关闭 PA0，当时角度偏差约 1.29°，未超 2°。日志没有足够细粒度时间证明具体是哪一路超时。代码检查发现 CANopen 任务在锁外取时、随后读取更新后的反馈可能产生无符号年龄下溢；0.2.8 修正为锁内同时取时和快照，并从快照判断状态字新鲜度。未放宽 250 ms 超时门限。

内部 `get_bench_steering.feedbackGateMask` 在故障时保存触发前最近的反馈门禁位：1 驱动器位置、2 行走速度、4 编码器、8 转向状态字、16 行走状态字、32 编码器配置、64 行走已使能、128 行走转速过高、256 PA0 关闭。它用于定位反馈门禁，不覆盖所有执行错误；执行故障另有 `fault` 字段。执行故障同步上报公共 `faultLatched=true`、`stopReason=13`，停止或旧租约不能清除。

已完成主动停止、停止续租停车、停机不回中。−5°停机后编码器保持 2906，控制器上下电后 6064 从 -85717 恢复 -83815；RAM 中位自动从 -72187 重建为 -70274，Flash 中位仍 -85123/3182。随后 +1° 跟随正常。wyse 确认两次供电首次使能分别写入一组新软限位，同一供电周期重启测试不会重复平移。

反馈失效通过 wyse 单次 NMT Stop Node 2 注入，使该节点不再提供 SDO 新反馈；ABox 在仍有续租时关闭 PA0，撤销许可并锁存执行故障，之后 24 条控制请求被拒绝。恢复供电与通信后，再发旧会话续租仍返回拒绝，两节点状态均未使能。该测试验证真实 CANopen 反馈中断链路，不是物理拔线或接触器断电时间验收。

结束后已关闭 PA0 并普通重启验证：0.2.9 CONFIRMED、中位保留、RAM 许可/坐标清空、无运动使能。主机全套回归通过，包括新增上电坐标、溢出、重复样本、限位只平移一次、模式不匹配、使能未到达与故障锁存用例。

本次只发布具备 RAM 许可的转向能力，通用运动与行走保持关闭。正式 `dist/` 必须由发布脚本整体生成，并在替换前证明 App 与上述已实测候选字节一致。整车接触器反馈、本地安全输入、物理断链/断电时延和独立角度精度验收仍未完成；行走执行与低速换向留待下一阶段，仍须零速发送、连续三次新反馈 ≤20 rpm、2 秒超时锁存。
