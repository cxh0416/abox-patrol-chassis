# 巡防车底盘项目交接与接手指南

本指南是 `patrol_vehicle_chassis` 的内部接手流程。当前状态、正式包和未完成验收以 [CURRENT](../CURRENT.md) 为入口；正式固件身份以 [dist 清单](../../dist/release.manifest.json)及文件实际哈希为准。本文的命令供接手人员在自己的工作区执行，不能把源码、主机测试、ARM 构建、共享标准板和本车现场结果混为一项验收。

## 合并后的共同测试基线

运动控制来自 `liujiek/ljk@192fe580`，公共 TLS、授时和 MQTT 报文预算来自原 `main@6bdc1aa`，平台固定 `d3d940505eb5c534c83858fdc754f2c4ab5ac879`。新版本为 `patrol-chassis-0.2.106`，正式包使用 `PATROL_ACTIVE_CAR=0` 和板上 Config V5。主机验证和正式构建不替代实车验收。

同事在自己的 fork 工作区先保存本地改动，再执行以下命令；`upstream` 已存在时核对其 URL 后省略添加命令。新测试分支从共同 main 建立，后续改动再提交回来。

```powershell
git remote add upstream https://github.com/cxh0416/abox-patrol-chassis.git
git fetch upstream main
git switch -c ljk/test-0.2.106 upstream/main
git submodule update --init --recursive
.\tools\run_tests.ps1
.\platform\tools\build_product_release.ps1 -ProductRoot (Get-Location).Path -AppVersion patrol-chassis-0.2.106
```

`dist/` 不纳入 Git，同步源码后须执行正式构建或单独交接整套正式包，并核对包内 manifest 与实际 SHA256。需要测试候选时显式使用 `.\tools\build_bench_steering.ps1 -Drive -EnableActuation -ActiveCar 0`，避免脚本的逐车默认值影响共享测试基线；候选不替代正式包。新现场记录应包含实际包哈希、设备/车辆标识、Config V5 和操作条件。

现场继续验证实际转角差速（左右转、前进/倒车、9°/11°档位）、零速/换向和 6 秒期限、热复位后撤使能、遥控切换/断链/制动、回中与 CAN2 标定。普通运动取消实时双角 2° 门禁；标定和回中校验仍保留。先架空低速测试，不能用 MQTT ACK 或主机模拟结果代替实测。

## 本地环境与检出

正式构建使用 PowerShell 7（`pwsh`）；Windows PowerShell 5.1 不支持公共发布脚本中的无符号数字语法。其余开发工具为 Git、Python、CMake、Ninja、MinGW 主机 GCC 和 Arm GNU Toolchain 14.2（`arm-none-eabi-gcc`/`objcopy`/`objdump`）。首次接手先确认这些命令可在 PowerShell 的 `PATH` 中找到；构建脚本本身使用 `Get-Command gcc` 和 CMake Ninja 生成器。服务端本地测试另需 Python 依赖与 Node.js；服务仓的 Windows 发布脚本在需要重建归档时调用 WSL `Ubuntu-22.04`，部署环境和凭据按其部署说明准备，不照搬开发机路径。

```powershell
git clone --recurse-submodules https://github.com/cxh0416/abox-patrol-chassis.git abox-patrol-vehicle-chassis-firmware
Set-Location .\abox-patrol-vehicle-chassis-firmware
git submodule update --init --recursive
git submodule status
git status --short
Get-Command pwsh,python,gcc,cmake,ninja,arm-none-eabi-gcc,arm-none-eabi-objcopy,arm-none-eabi-objdump
```

子模块提交应由本产品 Git 索引确定；若维护本地已有检出，先记录产品 HEAD 和 `git status`，再执行 `git submodule update --init --recursive`，不要在 `platform` 里自行切到最新分支。单独获取服务仓时，在另一目录运行 `git clone https://github.com/cxh0416/device-ota.git`，先读该仓 `README.md`、`docs/CURRENT.md`、`docs/operations/development-baseline.md` 与 `docs/chassis-bench-control.md`。服务端 Python 依赖在 `requirements.txt`；Windows 本地用于隔离测试，生产 API 与 worker 按服务仓 Linux 部署流程运行。

## 从测试到产物

在本产品仓根目录执行：

```powershell
.\tools\run_tests.ps1
.\tools\build_bench_steering.ps1
.\tools\build_bench_steering.ps1 -Drive
```

第一条先跑产品 Python 单测，再用主机 GCC 编译产品 C 夹具，并通过 CMake/Ninja 构建、CTest 验证固定的公共平台。`-SkipPlatformTests` 只用于已有平台主机构建的差异复核，不能当首次完整验证。相关实现和断言见 [源码模块与依赖](../implementation/源码模块与依赖.md)及 `tools/run_tests.ps1`。

台架候选使用 `.\tools\build_bench_steering.ps1`；行走候选加 `-Drive`，需要真实执行输出的受控台架候选再加 `-EnableActuation`。输出分别在 `out/candidates/bench-steering/`、`out/candidates/bench-drive/`。在线调试包使用 `.\tools\build_online_debug.ps1`，输出在 `out/debug/online/`。这些脚本先校验暂存产物，再由 `tools/artifact_store.py` 整体替换对应目录；每类只保留最近一次成功构建。临时日志放 `out/logs/`。

正式包入口是 `platform/tools/build_product_release.ps1 -ProductRoot <本仓绝对路径> -AppVersion <patrol-chassis-x.y.z>`；它调用产品 `tools/build_release.ps1`，要求产品和平台工作树干净、冻结 Boot 哈希与 Flash 分区正确，校验暂存目录后整体替换 `dist/`。需要从经台架验收的同一运动候选转正式包时，产品脚本支持 `-BenchDrive -EnableActuation -VerifiedCandidate <候选 App 路径>`，必须对照实际候选哈希；不能把示例参数当成现场批准。文档变更本身不触发重新打包。正式包生成也不执行 OTA；`dist/` 不放候选、诊断包或历史版本。清理先运行 `python tools/clean_workspace.py` 预览，确认后才显式加 `--apply`；清构建缓存另加 `--build`，不得清冻结 Boot 和逐车配置。

平台服务仓在自己的目录可先做隔离的本地验证（需已安装 Node.js）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
node tests/test_chassis_joystick.mjs
node tests/test_chassis_hold.mjs
```

这是当前远控相关前端用例示例；修改其他页面时按服务仓 `README.md` 选择其余用例。完整发布、目标环境核验和回退按服务仓 `README.md`、`docs/operations/development-baseline.md`、`docs/operations/ota-admin-cli.md` 执行。服务仓 `deploy/scripts/publish_server47.ps1 -DryRun` 可先检查发布准备；正式发布与设备 OTA 是不同动作，OTA 须经受控业务入口和设备终态 `CONFIRMED` 核验。服务仓代码、环境文件、数据库迁移及 worker 版本都要按目标服务器实时读回，不能仅凭本地仓的版本判断。

烧录脚本 `tools/flash_jlink.ps1` 是会改变设备状态的现场工具，只能在核对具体板卡、镜像、Boot State A/B、Config V5 及备份后按现场流程使用。Boot `0x08000000`、App `0x08008000`、State A/B `0x0803E800/0x0803F000`、配置页 `0x0803F800` 边界必须保持。正常接手与主机验证无需烧录。

## 为什么上电后没有运动许可

正式清单中的 `steering_executor_compiled`、`drive_executor_compiled`、`actuation_enabled` 均为 `true`，所以运动执行功能已编入正式包。`startup_motion_permit=false` 是上电安全默认值：`PatrolRuntime` 初始化时清掉旧会话、目标和使能请求；重启、MQTT 运行时变化、停止、租约到期或故障不会保留远控授权。当前服务前端先上电并创建会话，MQTT worker 发公共 V4 `acquire/renew`；固件 `RemoteService_HandleControl` 检查会话、序号和安全条件，`ChassisControl_Apply` 接受后才设置 `enable_request`。旧服务说明提到的 `arm_bench_drive` 不是目前 `cloud_protocol.c` 中的内部运维动作，也不是当前页面/worker 的接管步骤，不能依历史文字等待单独永久许可位。

即使上电命令成功，MCU 仍要求 Config V5 标定兼容、驱动器和独立编码器状态/范围、有效运行坐标、PA0 输出命令开启、两路新鲜转角和轮速、两节点在线、无 CAN Bus-Off/驱动故障/OTA 占用。平台还要启用 `PATROL_CHASSIS_REMOTE_ENABLED`、具备运维角色、设备在线且无冲突维护任务。平台 ACK、会话创建或 GPIO 命令状态都不代表车轮实际运动；本车无独立继电器/接触器触点反馈。换向必须先双零速，并连续三次取得左右实测 ≤20 rpm 的新反馈；6 秒超时撤销使能并锁存故障。

若问的是**某一台设备当前为何没有许可**，仓库不能给出实时原因。先只读核对设备上报版本与 `otaState`，再看最新状态的 `calibrated`、`steeringProfileReady`、`steeringRangeValid`、`powerReady`、`powerOutputOn`、`feedbackFresh`、`steeringOnline`、`driveOnline`、`encoderOnline`、`canBusOff`、`driveFault`、`otaBusy`、`safetyReady`、`stopReason`、`faultLatched`、两路实测转速与转角；必要时按当前运维接口读取 `get_can_diag`、`get_calibration`、`get_center_calibration_diagnostics` 和故障记录。裸标准板缺少真实轮速反馈时被拒绝是预期门禁行为。随后查平台远控开关、角色、会话状态、worker 实际派发与设备控制响应码。先保存带时间戳的原始状态和诊断，再按 [故障记录与复位](故障记录与复位.md)及 [逐车标定](巡防车底盘逐车标定与参数记录.md)处理；不要凭一个 `safetyReady=false` 猜测是软件未开放，也不要用复位绕过门禁。

3. 对本地空闲回中完成同一正式 App 的设备安装与真实转向/停车/接管验收。当前主机测试通过不等于回中机构到位或车辆可行驶。
4. 补本产品的冷上电与 pre-App 停机、完整蜂窝断网恢复、持续 OTA 下载/中断恢复、试运行确认及故障回滚证据；下载成功、Broker 收到消息或 `CONFIRMED` 字段的单次读回各有不同证明范围。
5. 在设备上测任务栈高水位；现有 `.su` 调用链加保留量只是静态估计。跨重启动作持久账本仍需独立设计与验证，现有 RAM 重放只覆盖本次运行。处理前先核对当前业务风险与平台既有保护，避免为交接项直接叠加新状态机。
