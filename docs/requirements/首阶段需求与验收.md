# 需求与验收

产品：`patrol_vehicle_chassis`。当前正式包为 0.2.13；本清单的当前能力面向 0.2.15 候选，尚待现场验收。

## 当前能力与门禁

- 独立编码器为 4096 count 单圈，机械中位固定为 2048；转向上限 ±30°，独立行走目标上限 ±200 rpm。每次控制仍受 RAM 许可和租约限制。
- 未标定、反馈过期、双角度偏差超过 2°、节点离线、CAN Bus-Off、驱动故障、OTA 忙、安全配置不兼容或编码器范围异常时禁止运动。
- 换向前先发送左右零速；双写入完成后必须取得连续三次左右新反馈绝对值 ≤20 rpm，2 秒超时撤使能并锁存。
- 未确认继电器、接触器反馈和本地按键引脚不绑定。PA0 命令状态不能证明实际供电或物理急停能力。

## 待现场完成

1. 机械中位提交后，连续读回编码器低字约 2048且高字为 0，并核对逐车驱动器中位保存。
2. 核对 0°、±20°、±30° 的驱动器与独立编码器反馈，并独立测量轮胎角度和机械余量。
3. 在 0°、±25°、±30° 意外掉电后正确恢复坐标，且不自动接管。
4. 在 ±35°/±40° 位置重启时拒绝接管；40° 请求必须在页面、平台和固件被拒绝。
5. 架空核对真实前后方向、低速行走及双轮换向停车；验证断网、断 CAN、编码器失效、驱动故障和 OTA 忙时的停止与撤许可。
6. 另行取得接触器反馈、本地安全输入、物理断链/断电时延和道路试验的证据。

正式发布要求现场证据对应准确候选 SHA256、产品及平台工作树干净、正式 App 与已验证候选一致、Flash 分区检查通过。构建成功、MQTT ACK 或单次 CAN 报文均不能代替真实动作验收。

## 早期阶段边界

第一阶段只交付安全空框架、CANopen 编解码、编码器解析、安全仲裁、电源状态机、MQTT 租约和主机测试，固件默认不发送运动命令。第二阶段只允许 Node 1/2 的 SDO 上传诊断，验证反馈链路，不包含真实运动、转向、电源或道路验收。

早期 `±1°..±5°`、`50..300 rpm` 和只读诊断属于对应版本的阶段目标，不是当前候选上限。历史结果保存在日期文档和 `docs/operations/evidence/`，不得直接作为当前固件的操作参数或验收结论。
